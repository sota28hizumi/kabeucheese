# kabeucheese：資料から、これまでの経緯を取り込む

会話の記録が無い過去の活動を、作業フォルダに残っている資料（メモ、報告書、スライド、ノートブック、コード、コミット履歴）から読み解き、「問い → 選択肢 → 決定」の地図にする。時期ごとに1つのセッションとして保存し、古い順に「前回 → 続き」で結ぶ。そのあとの普段の `/kabemap` は、最後の時期の続きとしてつながる。

論点・用語・決定の書き方は、通常の解析と同じ規則を使う。**最初に `../analyze/SKILL.md` を読み**、手順2（ノードと線）、手順4（用語カードと候補）、手順4b（追加された用語の確認）、「守ること」に従う。この文書は、資料から作るときに違う点だけを書く。

## 0. 一覧を取る

1. `mcp__kabeucheese__scan`（見つからなければ ToolSearch で `kabeucheese scan`）を呼ぶ。返るもの：
   - `folder`・`folderKey`・`root`（作業フォルダの絶対パス。読むときにだけ使い、保存しない）・`artifactUrl`・`now`
   - `files`：資料の一覧。各要素は `path`（`root` からの相対パス）・`kind`（note / office / pdf / notebook / code / data / image / other）・`size`・`modified`（更新日）・`firstCommit` / `lastCommit`（git で最初に入った日・最後に変わった日）。日付の古い順
   - `commits`：コミットの一覧（古い順。`date`・`subject`・`files`（変えたファイルの数））
   - `dateRange`、`byKind`、`totalFiles`、`truncated`（多すぎて一覧を削ったとき true）、`excludedSecretFiles`（機密らしい名前のため一覧から外した数）
   - `sessionIdPattern`：時期のセッション id の付け方
2. `artifactUrl` が空なら止まり、README の「はじめての設定」を案内する。`folder` が `未分類` なら止まる（読む範囲が決まらない）。
3. `ArtifactData` を ToolSearch で読み込む（`select:ArtifactData`）。

**日付の考え方**：ファイルの更新日はコピーやクラウドの同期で変わることがあるので、`firstCommit` があればそちらを優先する。ファイル名や本文に日付（`2025-06-12`、`20250612`、`第3回`、「中間発表」など）があれば、それがいちばん確か。

## 1. 前回までの取り込みと、このフォルダの記録を読む

- `get` で `imports/<folderKey>` を読む。あれば**追加の取り込み**（手順7）。無ければ初回。
- `query` で `sessions` を `where: [["folder", "==", "<folder>"]]`、`limit: 200` で読む。`source` が `"import"` のものは前回までに取り込んだ時期、それ以外は普段の `/kabemap` で作ったセッション。各文書の `version` を控える。
- `list` で `terms` を全部読む（`query.limit: 1000`）。照合と `occurrences` に使う。
- `get` で `meta/current` を読み、`version` を控える。
- `memos` には触らない。

## 2. 何を読むかを決める

ユーザーが範囲や時期を指定していれば（`/kabeimport` の引数）、それに従う。指定が無ければ、次の順に、合わせて**60ファイルほど**まで読む。

1. 経緯が書かれた資料：README、メモ・日誌・議事録、進捗報告、発表スライド、論文や報告書の原稿（`note`・`office`・`pdf`）
2. コミット履歴（`commits` の `subject` と日付）。方針の変化、試して戻した跡、名前の変更が分かる
3. ノートブックの見出しと Markdown のセル、主要なコードの冒頭のコメントや設定ファイル（何を試したかが分かる範囲だけ）
4. データ・画像・生成物は**中身を読まない**。名前と日付だけを手がかりにする（例：`results_v2/` ができた時期）

読み方：
- 長いファイルは見出しと冒頭を中心に読み、全部は読まない。PDF は `Read` の `pages` で最初の数ページ。
- Word・PowerPoint は、`anthropic-skills:docx` / `anthropic-skills:pptx` スキルのテキストの取り出し方を使う。読めなければ名前と日付だけを使う。
- 他人が書いた論文や配布資料（参考文献として置いてあるもの）は、論点の材料にしない。用語や「何を参考にしたか」の手がかりにだけ使う。
- 一覧から外された機密らしいファイル（`.env` など）や、本文に API キーやパスワードがあるファイルは読まない・書き写さない。

## 3. 時期に分ける

読んだ内容を時系列に並べ、**活動の段階が変わったところ**で区切る。目安：

- テーマや手法を切り替えた、発表・締め切り・提出があった、1か月以上手が止まっていた。
- 時期は1〜12個。1つの時期に問い3〜12個。資料が少なければ1つの時期でよい。
- 各時期に `from`・`to`（`YYYY-MM-DD`）を決める。重ならないように、古い順に並べる。

## 4. 時期ごとに論点を作る

`../analyze/SKILL.md` の手順2と同じノードと線を作る。資料から作るので、次を足して守る。

| フィールド | 中身 |
|---|---|
| `basis` | `stated`（資料にそう書いてある、または実際にそう作られている）／`inferred`（資料の流れからの推定）。ページでは `inferred` に「推定」と出る |
| `evidence` | 根拠になった資料の配列（1〜3個）：`{ "path": "<相対パス>", "date": "YYYY-MM-DD", "note": "<その資料のどこから分かるかを30字前後で>" }`。コミットなら `path` を `git:<日付> <件名の要約>` にする |

- **決定にするのは、資料ではっきり分かるときだけ**：「〜にした」「〜を採用」と書いてある、その後の資料やコードで実際にそうなっている、のどちらか。計画や案の段階のものは、問いを `open: true` にし、選択肢を `status: active` のまま残す。
- 試して**やめた跡**があれば（コードやメモから消えた、後の資料で「やめた」とある）、その案を `status: rejected` にする。いったん決めて後で変えたなら、古い決定を `superseded` にして新しい決定と `revised` の線で結ぶ。時期をまたぐなら、古い時期の文書の `edges` に `toSession` 付きの `revised` を足す（`../analyze/SKILL.md` の手順3b-2と同じ形）。
- `detail` には「なぜそうしたか」を書く。資料に理由が無ければ推定であることを書き（「〜のためと思われる」）、`basis` を `inferred` にする。
- 資料の原文を長く写さない。要約した言葉で書く。共同研究者・指導教員などの個人名は書かず、役割で書く（「指導教員の助言で」）。
- 時期の最後に、次の時期へ持ち越した問いがあれば `open: true` のまま残し、次の時期で決まったらそちらに決定を置く（`continued` の線でつながる）。

## 5. 時期の文書を組み立てる

各時期を1つのセッション文書にする。

```json
{ "id": "imp-<folderKey>-<from の YYYYMMDD>", "folder": "<folder>", "source": "import",
  "title": "<時期の名前（20字前後。例：手法の比較と予備実験）>",
  "summary": "<この時期に考えたこと・決めたことを2〜3文>",
  "period": { "from": "YYYY-MM-DD", "to": "YYYY-MM-DD" },
  "startedAt": "<from>T00:00:00.000Z", "updatedAt": "<to>T23:59:59.000Z", "importedAt": "<now>",
  "previousSessionId": "<ひとつ前の時期の id。最初の時期なら書かない>",
  "sources": [{ "path": "…", "date": "YYYY-MM-DD" }],
  "nodes": [...], "edges": [...], "candidateTerms": [...] }
```

- `updatedAt` は**取り込んだ時刻ではなく、時期の終わり**にする。こうすると、取り込んだ時期は普段のセッションより古い順に並び、次の `/kabemap` は最後の時期を「前回」として結ぶ。`to` が今日より後にならないようにする。
- `sources` は、その時期に実際に読んだ資料（最大40件）。読んでいない資料は入れない。
- 2つ目からの時期には、`../analyze/SKILL.md` の手順3b-1と同じ `continued` の線（`id: "c1"`、`toSession` はひとつ前の時期）を足す。

**普段のセッションとのつなぎ**：このフォルダに普段の `/kabemap` で作ったセッションがあり、そのうち `startedAt` がいちばん古いものに `previousSessionId` が無く、最後の時期の `to` より後に始まっていれば、そのセッションを最後の時期の続きにする。`update` で `previousSessionId` と `edges`（`continued` の線を足した全体）だけを書き、`updatedAt` やほかのフィールドには触らない。

## 6. 用語

`../analyze/SKILL.md` の手順4・4bと同じ。研究分野の専門用語、手法名、データセット名、評価指標など、あとで見返すときに説明が要るものを用語か候補にする。`contextMeaning` には「この活動でどう使ったか」を書く。`occurrences` の `sessionId` は時期の id、`nodeId` はその時期の論点。資料に定義が書いてあっても、確かでないことは書かない。

## 7. 追加の取り込み（2回目から）

`imports/<folderKey>` があるとき：

- `files` の一覧と見比べ、**新しいファイルと、更新日が変わったファイルだけ**を読む（ユーザーが範囲を指定したときはそれに従う）。新しいコミットも、前回の `importedAt` より後のものだけ見る。
- 前回までの時期の id・ノードの id は変えない（メモが id で結び付いている）。新しい資料がある時期の範囲に入るなら、その時期の文書に論点を足したり、`detail` を深めたりする。範囲より後なら、新しい時期を足す。
- 普段の `/kabemap` で作ったセッションの期間（`startedAt` 〜 `updatedAt`）に入る資料は、そのセッションですでに話した可能性が高いので、新しい時期は作らず、足りない根拠があればそのセッションの論点を変えずに済むか見る。迷ったら足さない。
- 時期の文書を消すのは、明らかな誤りだったときだけ。

## 8. 確かめてから書き込む

書き込む前に、ユーザーへ次を短く示し、書き込んでよいか確かめる（一度だけ）：

- 読んだ資料の数と、読まなかったもの（種類ごとの数、機密らしいため外した数）
- 時期の一覧：期間・名前・問いと決定の数・推定の論点の数
- 新しく作る用語の名前

ユーザーが直してほしいと言えば直してから書く。そのあと `ArtifactData` の `batch` で書く（1回に50件まで。多ければ分ける。新しい文書は `if_version` なし、既存は控えた version を付ける）：

1. 時期の文書（`sessions/imp-…`）
2. つないだ普段のセッションの `update`（手順5）、時期をまたいで覆した決定の書き換え（手順4）
3. 用語（新しいものは `set`、既存は `update` で変わったフィールドだけ。`occurrences` は全体）
4. `imports/<folderKey>` を `set`：
   ```json
   { "folder": "<folder>", "importedAt": "<now>", "sessions": ["imp-…", …],
     "files": [{ "path": "…", "modified": "YYYY-MM-DD", "firstCommit": "YYYY-MM-DD" }],
     "lastCommit": "<読んだ最後のコミットの日付>", "readCount": <読んだ資料の数> }
   ```
   `files` は `scan` が返した一覧の全部（読んだかどうかに関わらず。次回の差分に使う）。絶対パスや `root` は書かない。
5. `meta/current` を `set`：`{ "folder": "<folder>", "sessionId": "<最後の時期の id>", "updatedAt": "<now>" }`（既存なら `if_version`）。ページはここを開く。

version の不一致で断られたら、その文書を読み直してから書き直す。

## 9. ペインを開いて伝える

`mcp__kabeucheese__show` を呼ぶ：

- `title`：`これまでの経緯（<folder>）`
- `summary`：活動全体の流れを2〜3文
- `continuesFrom`：空文字
- `items`：時期の古い順に、各時期の問いと決定（覆った決定は `superseded: true`、まだ決めていない問いは `open: true`）。多ければ決定とまだ決めていない問いを優先し、80個まで
- `counts`：全時期の合計（`decisions` は覆っていない決定の数）
- `newTerms`、`candidates`：新しい用語と、全時期の候補（最大20個）

最後にユーザーへ、取り込んだ時期の数と期間、推定の論点の数、新しい用語、普段のセッションとつないだかどうかを2〜4行で伝え、Artifact の URL を `#s-<最初の時期の id>` 付きで示す。推定の論点はページで「推定」と出るので、違っていればページのメモに書くか、会話で直すよう伝える。
