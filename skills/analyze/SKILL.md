# kabeucheese：会話を論点の地図にする

このセッションの壁打ちを、あとから見返せる「問い → 選択肢 → 決定」の地図と用語カードにして、kabeucheese Artifact のデータベースに保存する。最後にペインを開く。

## 0. 前提を取る

1. `mcp__kabeucheese__context`（名前が見つからなければ ToolSearch で `kabeucheese context` を探す）を呼ぶ。`sessionId`・`folder`・`artifactUrl`・`now` が返る。`now` は今の時刻（UTC の ISO 文字列）で、以降「今」と書いた時刻にはすべてこの値をそのまま使う。時刻を自分で推測したり、`+09:00` などの書き方に直したりしない（`updatedAt` は文字列のまま並べ替えるので、書き方が混ざると「前回」の判定がずれる）。`artifactUrl` が空なら保存先が未設定なので、ここで止まり、README の「はじめての設定」を案内する。ツールが無い環境では、`sessionId` は不明として止まり、ユーザーに kabeucheese Mod が入っているか確かめてもらう。
2. `ArtifactData` を ToolSearch で読み込む（`select:ArtifactData`）。以降の読み書きはすべて `url: artifactUrl` で行う。

## 1. 前回のデータを読む

- `get` で `sessions/<sessionId>` を読む。あれば、その `version` を控える（書き込み時の `if_version`）。無ければ新規。
- `list` で `terms` を全部読む（`query.limit: 1000`）。既存の用語の `id`・`name`・`occurrences`・`version` を控える。
- `get` で `meta/current` を読み、あれば `version` を控える。
- **前回のセッション**を決める（`folder` が `未分類` のときは決めない）：
  - このセッションの文書がすでにあり、`previousSessionId` が入っていれば、それをそのまま使う（変えない）。
  - 文書がまだ無いか `previousSessionId` が無ければ、`query` で `sessions` を `where: [["folder", "==", "<folder>"]]`、`order_by: { field: "updatedAt", direction: "desc" }`、`limit: 10` で読み、`id` がこのセッションと違う最初の1件を前回とする。1件も無ければ前回なし。
  - 前回があれば、その文書の `nodes`・`edges`・`version` を控える（手順3bで使う）。
- `memos` コレクションには**触らない**（読みも書きもしない）。ユーザーがページで書いたメモはそこにあり、論点・用語の id で結び付いている。だから**既存の論点・用語の id は変えない**。

## 2. 会話全体を見直して論点を作る

このセッションの最初から今までの会話を読み、ユーザーが何を考え、何を比べ、何を決めたかを拾う。会話の原文は書かず、短く要約した言葉で書く。

### ノード（`nodes` の各要素）

| フィールド | 中身 |
|---|---|
| `id` | セッション内で一意。英数字と `-` `_` だけ（例：`q1`, `o1-2`, `d1`）。既存のノードは id をそのまま使う |
| `kind` | `question`（問い）／`option`（選択肢）／`decision`（決定）／`superseded`（覆った決定） |
| `label` | 一行の見出し。30字前後まで。問いは「〜か？」「〜をどうするか」の形 |
| `detail` | 2〜4文の中身。なぜそう考えたか、何が決め手か |
| `status` | `active`／`rejected`（選ばなかった案）／`superseded`（変更前の決定） |
| `parent` | 流れ図での親ノードの id。問いの根は `null` |
| `parentKind` | 親との関係。ふつうは `derived`（派生）。決定の根拠になった選択肢なら `reason`、前提から出た問いなら `premise` |
| `order` | 兄弟の中での並び順（数値） |
| `terms` | このノードに付ける用語の id の配列 |
| `open` | 問いだけ。まだ決めていない問いなら `true`（ページとペインで「未決」と出る）。決まったら `false` にする |

作り方：

- 問いを根にして、その下に選択肢、選んだ選択肢の下（または問いの直下）に決定を置く。決定から次の問いが生まれたら、その問いを決定の子にする。
- 選ばなかった選択肢も消さずに `status: rejected` で残す（ページでは灰色になる）。
- **決定にするのは、ユーザーが決めたとはっきり分かるときだけ**。ユーザーが選んだ、提案に「それで」「OK」と答えた、「既定で」「おまかせ」と明示的に任せた、のどれか。
- 「A が良さそう」「B も気になる」「たぶん A」のように迷っている段階や、Claude が勧めただけでユーザーが答えていないものは決定にしない。その問いは `open: true` にし、選択肢はどれも `status: active` のまま残す（どれかを `rejected` にもしない）。
- 前回 `open: true` だった問いがこの会話で決まったら、決定を足して `open` を `false` にする。
- 細かすぎる話（ツールの使い方の確認、誤字の修正など）はノードにしない。目安は1セッションで問い3〜15個。

### 枝をまたぐ線（`edges` の各要素）

親子関係で表せないつながりだけを書く：`{ "id": "e1", "from": "<node id>", "to": "<node id>", "kind": "..." }`

- `compared`：選択肢どうしを比べた
- `reason`：あるノードが別の枝の決定の理由になった
- `premise`：あるノードが別の枝の前提になった
- `revised`：覆った決定（from）→ 新しい決定（to）
- `reference`：別のセッション（別フォルダでもよい）の論点を参照した。`toSession` に相手のセッション id を入れる。相手は `query` で `sessions` を `folder` で絞って探し、その `nodes` から一致する論点の id を `to` に入れる。見つからなければ線は引かない
- `continued`：前回のセッションの続き（手順3b）。`toSession` に前回のセッション id を入れる

`toSession` が付いた線は、線を書いた文書の `from` から、別セッションの `to` へ向かう。ページでは線の代わりに、押すと相手のマップへ飛ぶチップとして両側に出る。

## 3. 前回との差分のとり方（再実行時）

- 前回のノードは id を保ったまま残す。中身が深まっていれば `label` や `detail` を書き直してよい。
- 新しい論点は新しい id で足す（前回の最大番号の続き）。
- 決定が覆ったら、古い決定を `kind: superseded`、`status: superseded` に変え、新しい決定を足して `revised` の線で結ぶ。古い決定は消さない。
- 前回のノードを消すのは、明らかな誤りだったときだけ。

## 3b. 前のセッションの続き

手順1で前回のセッションが決まったときだけ行う。

1. **続きの線**：このセッションの文書に `"previousSessionId": "<前回のid>"` を入れる。さらに `edges` に次の1本を足す（すでにあれば足さない）。
   ```json
   { "id": "c1", "from": "<このセッションの最初の問いのid>", "to": "<前回のノードのid>", "toSession": "<前回のid>", "kind": "continued" }
   ```
   `to` は、この会話が受け継いだ前回の論点。はっきりしなければ、前回の覆っていない決定のうち `order` がいちばん大きいもの、決定が無ければ最後のノードにする。
2. **前回の決定を覆したとき**：この会話で、前回のマップにある決定を変えた場合は、前回の文書を書き換える。
   - その決定を `kind: superseded`、`status: superseded` にする。
   - 前回の文書の `edges` に、新しい決定へ向かう線を足す：`{ "id": "x-<このセッションidの先頭8文字>-<連番>", "from": "<前回の決定のid>", "to": "<このセッションの新しい決定のid>", "toSession": "<このセッションのid>", "kind": "revised" }`
   - 前回の文書の `updatedAt` は**変えない**（変えると、次のセッションの「前回」がずれる）。代わりに `revisedAt` に今の時刻を入れる。ほかのノードやタイトルにも触らない。
   - 覆したかどうかは会話の中身で判断する。はっきり別の結論に変えたときだけで、同じ決定を詳しくしただけなら覆したことにしない。
3. 前回より前のセッション（同じフォルダ）の決定を、会話がはっきり名指しして覆したときは、そのセッションにも 2. と同じことをする。名指しが無ければ前回だけを見る。

## 4. 用語カード

ユーザーが「○○について教えて」「○○って何？」と聞いた言葉、または壁打ちの中で説明が必要だった専門用語を用語にする。用語集は全セッション共通。

| フィールド | 中身 |
|---|---|
| doc id | 英数字と `-` の短い名前（例：`artifact-db`、`local-marketplace`）。既存の用語と同じものなら、その id を使う（下の「既存の用語との照合」） |
| `name` | 表示名 |
| `aliases` | 同じものを指す別の書き方の配列（英語名・略称・表記の揺れ。例：`["Artifact DB", "db 機能"]`）。無ければ空配列 |
| `definition` | ひとこと定義（40字前後） |
| `contextMeaning` | ユーザーの今の文脈で何を意味するか（1〜2文） |
| `explanation` | 詳しい説明。段落ごとの文字列の配列（2〜4段落） |
| `examples` | 具体例の配列（1〜3個） |
| `related` | 関連用語の id（または名前）の配列 |
| `source` | `{ "type": "web", "urls": [...] }` は、このセッションで WebSearch や WebFetch などで実際に確かめた URL があるときだけ。それ以外は `{ "type": "claude", "urls": [] }` |
| `occurrences` | `[{ "folder", "sessionId", "nodeId" }]`。既存の用語では、前回の配列にこのセッションの分を足した全体を書く（配列は丸ごと置き換わるため） |
| `updatedAt` | ISO 時刻 |

用語のためだけに新しく Web 検索はしない（ユーザーが頼んだときは別）。

**既存の用語との照合**：新しく用語を作る前に、手順1で読んだ用語の `name` と `aliases` の全部と見比べる。大文字・小文字、全角・半角、「の」「・」や空白の有無、英語と日本語の言い換えの違いだけなら同じ用語とみなし、既存の id に `occurrences` を足す。今回の書き方が既存の `name` とも `aliases` とも違えば、`aliases` に足す（`update` で配列の全体を書く）。意味が違うもの（同じ名前で別の概念）は別の用語にし、`name` で区別が付くようにする。

## 5. 書き込む

`ArtifactData` の `batch` で書く。1回に50件まで。多ければ分ける。

1. `sessions/<sessionId>` を `set`：
   ```json
   { "id": "<sessionId>", "folder": "<folder>", "title": "<20字前後のセッション名>",
     "summary": "<このセッションで考えたことを2〜3文>", "startedAt": "<前回の値。新規なら今>",
     "updatedAt": "<今>", "previousSessionId": "<前回のid。無ければ書かない>",
     "nodes": [...], "edges": [...] }
   ```
   既存なら `if_version` に控えた version を付ける。
   手順3bで前回の文書を書き換えたときは、同じ batch に、前回の文書の `set`（控えた version を `if_version` に）も入れる。
2. 用語：新しい用語は `set`（`if_version` なし）、既存の用語は `update` で変わったフィールドだけ（`occurrences` は全体）を `if_version` 付きで。
3. `meta/current` を `set`：`{ "folder": "<folder>", "sessionId": "<sessionId>", "updatedAt": "<今>" }`（既存なら `if_version`）。

version の不一致で断られたら、その文書を読み直してから書き直す（相手の変更を上書きしない）。

## 6. ペインを開く

`mcp__kabeucheese__show`（見つからなければ ToolSearch で `kabeucheese show`）を、次の形で呼ぶ：

```json
{
  "title": "<セッション名>",
  "summary": "<2〜3文>",
  "continuesFrom": "<前回のセッション名。前回なしなら空文字>",
  "items": [
    { "kind": "question", "label": "…" },
    { "kind": "question", "label": "<まだ決めていない問い>", "open": true },
    { "kind": "decision", "label": "…", "superseded": false },
    { "kind": "decision", "label": "…", "superseded": true },
    { "kind": "decision", "label": "<この会話で覆した前回の決定>", "superseded": true, "previous": true }
  ],
  "counts": { "questions": 0, "decisions": 0, "terms": 0 },
  "newTerms": ["このセッションで新しく登録した用語名"]
}
```

`items` は流れ図の順（問いのあとにその決定）。`counts.decisions` は覆っていない決定の数、`counts.terms` はこのセッションのノードに付いた用語の数。

前回のセッションで覆した決定は、`previous: true` を付けて `items` の最後に並べる。

最後にユーザーへ、足した論点・覆った決定（前回の分も）・新しい用語と、どのセッションの続きとして結んだかを2〜4行で伝え、Artifact の URL を示す。

## 守ること

- **会話の原文を書かない**。要約した論点・決定・用語だけを書く。
- 学籍番号・住所・電話番号・メールアドレス・パスワード・個人名など、個人を特定できる情報は書かない。企業名や研究テーマは論点に必要なら書いてよい。
- API キー・トークン・秘密鍵・パスワードの値は書かない。「API キーを環境変数に置くことにした」のように、値を含めずに書く。Mod は保存先への書き込みにそれらしい文字列があると止める。止められたら、その部分を消すか伏せ字にして書き直す。
- Artifact は自分専用のまま。共有の設定は変えない。
- `memos` には書かない。既存の id を変えない。
